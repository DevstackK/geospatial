How to run this end to end

Use this app to prepare the config. Run the Python backend where it can reach PostGIS and Oracle.

Prerequisites

Before execution
PostGIS database

Create or connect a PostgreSQL database with PostGIS enabled. Supabase, Neon, Aurora Postgres, Cloud SQL, RDS, or a VM can work if the PostGIS extension is available.

CREATE EXTENSION IF NOT EXISTS postgis;
Geospatial source table

Load the working dataset into PostGIS with a geometry column, stable ID column, and the attributes you want to validate.

public.parcels · geom · parcel_id
Oracle access

Have a reachable Oracle database, a staging table name, target table name, key columns, and a user allowed to create/load/merge.

ORACLE_DSN · ORACLE_USER · ORACLE_PASSWORD
Backend runner

Run the Python cleaner locally, on a VM, Cloud Run, ECS, Render, or another worker. Do not run large GIS jobs in the browser.

pip install -e ".[postgis,oracle]"

Use the app

Pipeline mode
  1. Enter PostGIS details. Set the source table, geometry column, ID column, target CRS, and required columns.
  2. Set cleaning rules. Add columns to trim, confirm category mappings, and keep the bounds check for longitude/latitude output.
  3. Enter Oracle write-back details. Set the staging table, target table, export/source table, key columns, and all columns that should be merged back.
  4. Download the YAML. Save it as config/oracle-output.yaml in the backend project.
  5. Run dry-run first. Review the generated SQL plan and audit before allowing execution.
  6. Execute only after review. Run execute mode after validating row counts, changed fields, and staging-table behavior.

Important limits

The browser app does not connect to databases or store credentials. It generates config. The Python backend does the database work.

For millions of records, keep execution close to the databases and use PostGIS for spatial operations.
